# 小a代码基线

基线日期：2026-09-10

这份文件记录当前代码的真实状态。它不是功能宣传，也不表示所有功能已经
达到生产质量。后续修改应更新“验证状态”和“已知问题”，避免仅凭一次输出
判断修复是否成功。

## 核心不变量

后续修改默认不得破坏以下行为：

1. `main.py` 持续接收多轮用户输入，`q` 正常退出。
2. `agent.py` 使用开放式模型—工具循环，不使用固定轮数替代正常结束条件。
3. 每个 `tool_use` 都产生匹配的 `tool_result`。
4. Subagent拥有隔离上下文；研究Subagent不修改工作区。
5. 工具权限和安全检查继续由Hook执行。
6. RAG只提供参考资料，最终结论仍由主Agent生成。
7. 持久化记忆失败不得阻止已经完成的主回答。
8. `.env`、记忆、日志、transcript、向量库和本地知识文档不进入Git。

## 已知问题（按建议处理顺序）

### P0：联网研究控制

- 搜索与页面核验没有独立预算；最近一次运行21次搜索、0次抓取。
- 子Agent预算不约束主Agent在同一用户回合内继续联网。
- 达到预算后DeepSeek仍可能生成已经不可用的联网工具调用。
- 子Agent报告是否完成目标没有根据证据覆盖率判断。

验收方向：先使用“只核验一个当前事实”的小测试，预期少量
`web_search` 后必须有 `fetch_url`，再运行完整旅行计划。

### P1：上下文压缩

- L2只按最近工具结果数量保留，可能删除日期、规则和已引用证据。
- L2占位符会建议模型重新调用工具，引起重复读取和搜索。
- 连续L4的fallback没有可靠继承上一份压缩摘要。
- 当前DeepSeek可能在摘要调用中耗尽输出预算但不返回文本。

验收方向：任意用户事实经过多次工具调用和连续两次压缩后仍存在；修复
不得通过把所有结果永久PIN或禁止必要的应急压缩完成。

### P2：持久化记忆

- `memory_select` 和 `memory_extract` 可能产生非法结构化输出。
- 项目记忆缺少状态、时间、来源和显式的更新/归档语义。
- 旧计划可能与当前用户更正同时存在。

验收方向：用户明确更正后新值可跨进程读取，旧值不再作为当前确认事实；
自动记忆失败仍不影响主回答。

### P3：任务状态与旅游交付

- 提出阻塞问题时Todo不一定进入 `waiting_for_user`。
- `completed` 可能与仍有普通未完成Todo同时出现。
- 正式旅行计划没有统一的结构和预算算术校验。

验收方向：阻塞澄清、可选追问和已完成任务可以明确区分；预算分项和总额
计算一致。

### P4：工程卫生

- `test/` 与 `tests/` 同时存在，分别包含pytest和unittest风格测试。
- transcript曾在单回合中重复全量写入。
- 存在空的实验文件和未完成模块，但本基线不擅自删除用户文件。

## 推荐迭代顺序

1. 先优化联网研究控制，不改主循环。
2. 用单一事实、小型行程、完整行程三级测试回归。
3. 单独修复L2，再单独修复L4摘要继承。
4. 上下文稳定后再改记忆生命周期和结构化输出。
5. 最后增加正式旅行计划的结构及算术校验。

每完成一项，创建一个独立Git提交，并在本文件记录测试结果。不要把多个
外围模块塞进同一个“修复所有问题”的提交。
