# Context 压缩升级记录

## 记录规则

上下文裁剪、工具结果压缩、摘要、请求预算和事实保真方面的实验、实现、
回退或评估均追加在此。隔离实验与进入生产管线的修改必须明确区分。

## 记录 01：修复无摘要丢事实和摘要故障退出（2026-10-01）

### 问题

- 历史超过 50 条时，即使总量只有几千字符，L1 也会直接删除中段；
- 上下文超过 L2 水位后，旧工具结果仅保留开头 400 字符，后部的价格、
  编号或来源可能消失；
- 超过 80,000 字符的摘要材料会机械删除中段；
- 摘要模型超时、限流或连接失败时异常直接外溢；
- 确定性兜底摘要遗漏 MCP 工具结果，并可能超过压缩目标。

### 原因

消息数量和字符水位被当成可以独立执行有损压缩的充分条件，但系统并不知道
任意文本中哪个字符是关键事实；摘要输入和失败路径又各自使用了不完整的
截断或白名单策略。

### 修改

- 生产管线不再仅因消息数量执行 L1，也不再对任意工具结果执行无摘要 L2；
  达到容量水位后统一进入有完整材料的 L4 摘要。`snip_compact` 与
  `micro_compact` 保留为兼容性/隔离测试函数，不再由正常管线调用；
- 摘要请求接收完整序列化材料，不再静默删除 80,000 字符后的中段；
- 摘要调用异常转入确定性兜底并记录异常类型，不让辅助模型故障退出主程序；
- 兜底保留 MCP 结果，截取单项时同时保留头尾，并对总摘要设置显式上限；
- `compact_history` 在目标更小时继续约束已经生成的摘要，避免压缩后立即再次
  超限；
- 主 Agent 在实际请求组装后，把系统提示词、工具 Schema、注入记忆和历史
  一起估算，必要时按剩余历史预算提前压缩。

### 验证方法

用无网络测试分别构造：60 条短消息的中段返程要求、约 40k 字符工具结果中
第 501 字符后的预订编号、90k 字符材料的中段预算、摘要调用超时、MCP 距离
结果以及超大兜底摘要；另验证实际请求预算包含系统提示词和注入记忆。

### 实际结果

上述事实均在对应生产路径或兜底摘要中保留；摘要超时返回兜底而不抛出；
兜底结果低于默认 30k 目标。压缩、主循环、恢复和 Shell 专项回归 48 项通过；
小 A 全量回归 129 项全部通过。

### 当前状态

修改已接入正式 `apply_compaction_pipeline`、`compact_history` 和主 Agent 请求
路径，不是隔离实验。

### 剩余工作

- 字符估算仍不是模型 tokenizer 的精确 token 计数，最终仍保留服务端
  `context_length` 应急恢复；
- 单个超大工具结果的 L3 落盘仍只把有限预览放进上下文，完整原文保存在本机
  文件中。关键 provider 应继续优先使用结构化 reducer，不能声称任意超大
  自由文本都可无损压缩；
- 若完整摘要请求本身超过提供方上下文且摘要服务同时失败，确定性兜底仍只能
  在有限预算内保留代表性内容，此时应向用户重新确认影响结论的缺失信息。
