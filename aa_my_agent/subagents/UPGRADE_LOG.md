## 记录 01：研究缓存误复用隔离评估（2026-10-02）

### 问题

同一用户回合中，不同城市、不同事实的研究请求可能复用不相关的旧研究报告。

### 原因

`research_scope` 仅将任务分为 web/rag/general；ResearchManager.resolve 用 requested_scope.issubset(cached_scope) 判断能否复用，没有比较城市、日期、研究对象或事实集合。successful_subagent_report 只检查报告的完成标志，不能证明该报告覆盖新问题。runner 的正常结束路径也没有以事实覆盖率证明 objective_met。

### 本次变化

新增本记录。未修改研究管理器、子 Agent 执行器或主 Agent 逻辑。

### 验证方法

使用内存中的 telemetry 替身加载 research_manager.py，未创建真实子 Agent 或模型请求。先缓存“联网核验杭州某博物馆开放时间”的成功报告，再 resolve“联网核验上海另一景点票价”。两项任务仅共享 web 分类，城市、对象和事实不同。

### 实际结果

第二项请求返回 reused=true，且 reused_output 与杭州开放时间报告完全相同。证明存在可复现的错误缓存命中，而不是对模型行为的猜测。既有批处理复用测试未覆盖这种不同研究目标的反例。

### 当前状态

隔离评估已完成；误复用缺陷尚未修复或接入生产修复。该探针没有联网、外发数据或修改任何旅行记录。

### 剩余工作

先仅复用规范化后完全一致的研究请求，再考虑按实体、日期、事实键及证据有效期实现覆盖检查；区分批处理结果引用与后续任务缓存；补充不同城市、不同日期和不同问题不得误复用的回归；研究完成状态由已取得证据与明确的未完成事实共同决定。
