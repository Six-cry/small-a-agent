# Tools 子系统升级记录

## 记录规则

每次对工具执行、安全边界或权限行为进行有意义的实验、实现、回退或评估，
都在本文件追加记录，并保留历史结论。

## 记录 01：敏感文件访问保护

### 问题

文件工具可以读取工作区内的 `.env`、私钥和凭据文件；工作区子 Agent 复用
同一批底层处理函数，Shell 也可以直接引用这些路径。

### 原因

原有 `safe_path()` 只验证路径是否位于工作区，未区分普通项目文件与敏感
文件；Shell 执行前也没有独立的敏感路径硬拒绝规则。

### 修改

- 新增集中式敏感路径策略，保护环境变量文件、常见凭据文件、私钥容器，
  以及 `.ssh/.aws/.azure/.kube/.gnupg/.git` 目录；
- `.env.example/.sample/.template` 继续允许读取；
- `safe_path()` 在路径解析后执行策略，因此读、写、编辑工具及其子 Agent
  复用入口都会受到保护；
- Glob 对直接敏感模式返回拒绝，并从普通通配结果中过滤敏感路径；
- Shell 在启动进程前拒绝常见敏感路径的直接引用。

### 验证方法

运行新增敏感文件测试、小 A 本地测试和根目录 RAG/参考测试。

### 实际结果

- 新增敏感文件保护测试 5 项全部通过；
- 小 A 全量本地回归为 52 项通过、3 项失败；3 项失败均来自既有
  `test_time_tool.py` 假配置缺少 `RAG_ALLOW_ON_DEMAND_IMAGE_VERIFY`，
  与本次修改无关；
- 根目录 RAG/参考回归 81 项及 24 个子测试全部通过，仅保留既有的
  `langchain-community` 弃用警告；
- 实测 `.env`、`.env.local`、私钥、云凭据、`.git` 路径均被拦截，普通
  通配不会返回敏感文件，`.env.example` 仍可正常读取；测试中的敏感
  Shell 命令在启动进程前被拒绝，没有执行。

### 当前状态

已进入正式工具执行路径并通过回归；这不是隔离实验。

### 剩余工作

本记录只覆盖敏感文件保护。Shell 的完整语法安全、Subagent 权限继承和
S11 错误恢复不在本次修改范围内。当前 Shell 拦截覆盖普通直接路径引用；
任意 Shell 代码仍可能通过动态拼接构造路径，彻底隔离需要后续单独收紧
Shell 执行边界，不能依赖路径关键字匹配提供系统级沙箱保证。

## 记录 02：关闭 Shell 首词自动放行（2026-10-01）

### 问题

权限 Hook 只根据 Shell 命令第一个词判断是否只读。`echo`、`dir` 等白名单
词后可以拼接管道、重定向、换行或第二条命令，整串内容会未经批准执行。

### 原因

审批器把“首个程序看起来只读”错误等同于“完整 Shell 程序只读”，而底层
执行器使用 `shell=True` 执行整条字符串。

### 修改

- 删除 Shell 首词自动放行；除硬拒绝规则外，所有 Shell 命令都需要用户确认；
- 审批界面以 JSON 转义形式展示完整命令，让换行和控制字符可见；
- 超过 32,000 字符、已无法合理审阅的命令直接拒绝；
- 持久化日志仍只记录脱敏摘要，不把完整命令写入日志。

### 验证方法

构造普通命令、`&`、`&&`、管道、重定向、换行、变量展开和命令替换；模拟
拒绝并检查底层 handler 调用次数，同时测试批准、硬拒绝和超长命令。

### 实际结果

未批准的所有命令均未到达执行器；批准的命令只执行一次；完整命令在本地
审批界面可见，控制字符不会直接作用于终端。相关专项测试通过，小 A 全量
回归 129 项全部通过。

### 当前状态

已进入主 Agent 与复用同一 Hook 的 Subagent 正式权限路径。

### 剩余工作

该修复提供“完整知情审批”，不是操作系统级 Shell 沙箱。用户批准后的命令
仍拥有当前进程权限；若将来需要无人值守运行，应改用参数化、无 Shell 的
专用只读工具，而不是重新增加首词白名单。
